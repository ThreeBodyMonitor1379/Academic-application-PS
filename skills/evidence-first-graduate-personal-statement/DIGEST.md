# 从一次一问到可提交文书：外显方法摘要

这项 skill 解决的不是“怎样把一句话写得更漂亮”，而是更早、更难的一层：当申请人的材料零散、记忆不完整、技术贡献边界模糊、学校要求会变化时，怎样在不替申请人回答的前提下，把事实变成一份可确认、可追溯、可排版的研究生申请文书。

它保存的是对话中可观察的方法，不是模型隐藏思维链。可观察的方法包括：先读材料和官网、保持用户指定的提问顺序、一次只问一个承重问题、把不同类型的“不知道”分开、纠正技术概念但不替用户制造经历、限制主张动词、让用户批准中文大纲，以及在官方格式不明确时诚实区分工作格式和学校要求。

## 1. 外层保序，内层自适应

用户给出表格时，好的访谈不应擅自重排他的栏目，也不应把丰富的项目经历无限追问到忘记原任务。方法是维护一个 `section_cursor`：外层按求学动机、学术准备、实践、职业目标、项目匹配和补充经历依次前进；每个栏目内部只追当前最影响写法的一项。

没有用户 schema 时，则切换到风险驱动：优先处理会改变事实可信度、个人归因、未来轨迹或合规性的缺口。两种模式都坚持一次一问，并采用同一输出：当前已确认什么、推荐如何界定、这轮只需要用户回答什么。

详见 [逐问质询协议](references/grilling-protocol.md)。

## 2. “忘记”“没有参与”和“不记录”不是同一回事

长访谈最容易失控的地方，是把任何短回答都视为“再追问一次就能恢复”。实际上：

- `forgotten` 表示经历存在但关键细节记不起；只允许一次会改变主张上限的恢复尝试。
- `none` 表示该栏目确实没有内容；记录后继续。
- `not_involved` 是个人贡献的负边界，不能被团队结果覆盖。
- `excluded_by_user` 表示申请人明确不要使用，后续不能因为缺素材而重新填回。
- `do_not_disclose` 是披露边界，不要求解释原因。

这种状态机的意义不是把访谈变成数据库，而是给“何时停止”一个可审计的答案。
同一项目同时出现多种状态时，要拆成多个原子主张或子项；一个字段不能同时代表“忘记参数”和“未参与算法”。
日志、文件或测量材料是否存在由 `evidence_availability` 单独记录；确认“没有日志”不能反向证明性能结果。只读审计不会写入项目工件。若误读排除来源，污染版本会标记失效并隔离，活动版本从允许来源重建，历史文件不在未授权情况下删除。

## 3. 纠正概念，但不夺走答案所有权

申请人可能准确记得自己做过什么，却对模型、通信链路、统计指标或系统边界的解释不够准确。Agent 可以做技术纠错，但必须同时保留两层：正确概念是什么，以及申请人当时实际做过、理解过或观察过什么。

正确解释不能倒灌成新的个人事实。Agent 也不能替用户生成动机、感受、顿悟、价值判断或职业志向。只有用户明确要求候选说法时，才可以依据已确认事实提供一版待确认文本。

## 4. 最强主张由最弱证据决定

技术项目里最危险的不是少写一个术语，而是把执行所有权误写成算法原创，把定性桌面观察误写成精度验证，把团队指标误写成个人成果，或把吞吐率误写成单帧时延。

因此，任何承重经历都要分开检查：核心方案从哪里来、本人修改了什么、在哪里测试、数字真正衡量什么、团队和个人分别取得什么。最终输出不是一个“贡献分数”，而是一张 claim boundary card：允许写到哪里、能用哪些动词、哪些说法仍没有证据，以及该经历应当进入正文、降级为未来目标还是排除。
已有数字但基线或比较条件不受控时，应明确标为未受控的量化输出；它既不是纯定性，也不能升级成受控性能证明。

详见 [最大可辩护主张校准](references/claim-calibration.md)。

## 5. Readiness 通过不等于申请人已经批准

证据充分只是第一道门。第二道门是申请人对内容的所有权：中文大纲必须列出每段的已确认事实、主张上限、个人/团队归因、未来连接、禁用内容和风险，然后由用户明确批准某个版本。

只有这两道门都通过，才进入英文全文。用户可以知情接受部分证据风险，但不能用一句“直接写”让系统静默跳过大纲确认。这样既防止 Agent 替用户制造人生故事，也让后续英文润色和版式调整不再悄悄改变事实。
readiness 也不能只看平均值：平均不高于 0.20 且每个维度都不高于 0.25 才算通过，防止一个完全未知的目标或证据维度被其他低分掩盖。

详见 [项目工件](references/project-artifacts.md) 与 [起草发布协议](references/drafting-and-release.md)。

## 6. 排版不能冒充官方要求

LaTeX 和 PDF 是交付工具，不是可信度来源。正式排版前必须核验当期官方 prompt、字数、文件类型、大小和版式要求。学校未规定字体时，可以采用用户指定或可读的工作格式，但必须明确说明它不是学校规定。

编译成功也不等于可以提交。还要检查字体、溢出、断页、页面密度、文件大小和每页视觉效果；没有执行视觉 QA 时必须直说。最终状态只能是 hold、等待大纲批准、带风险草稿或可供用户最终审阅，不能从“文件生成成功”推断授权提交。

## 7. 这套方法不做什么

它不保证录取，不替申请人提交，不把旧范文或成型 CV 当成动机来源，也不承担纯技术教学、CV 单条改写、单独的 prompt 解读或 programme-fit 研究。它的价值在于给完整文书建立一条清楚的证据链和两道发布门：写作者不需要猜，申请人仍然拥有自己的答案。
