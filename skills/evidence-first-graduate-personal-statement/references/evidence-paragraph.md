# 证据段落与弱项分支

在把证据地图转成正文、审查空泛能力声明，或处理成绩下滑、空档、转向等潜在弱项时读取本文件。

## 标准证据链

一个段落主要证明一个判断，并按下列逻辑组织；不要求机械地写成五个句子：

1. **主张**：本段要让评审得出哪项与 prompt 相关的资格判断？主张应具体、有限，不能只说“热情”“优秀”或“能力强”。
2. **本人行动**：用户本人在什么场景下做了什么，使用了什么方法，作出了什么有意义的选择？团队行动另行归因。
3. **证据**：有什么可观察产物、结果、反馈、后续用途或行为变化支持该主张？证据可以定性；只有来源支持时才使用数字。
4. **能力**：上述行动与证据允许推出什么能力？结论强度不能超过证据。
5. **未来贡献**：这项已证明的能力如何支持目标项目中的下一步学习、研究或有限参与？这是有依据的方向，不是保证成果。

可用骨架：

```text
[有限主张]。在[具体场景]中，我[本人动作、方法或选择]；[可观察证据]。
这使我形成/证明了[被证据支持的能力]，并可用于[与已核验目标相连的未来贡献]。
```

骨架只组织逻辑，不能替用户补事实。正式文风应服从目标 prompt 和学科情境。

## 团队与量化边界

科研、工程、实践或团队经历若存在来源、修改范围、验证环境、指标语义或动词强度歧义，先完成 [claim-calibration.md](claim-calibration.md) 的 Claim Boundary Card，再写本段；本文件不能替代该审计。

- 使用“团队取得 X；我负责 Y”区分集体结果与个人贡献。除非来源明确，不写“我领导”“我设计全部”“我使结果提升”。
- 每个数字记录口径、时间、范围和来源。无法核验的比例、排名、用户量、准确率、节省金额或影响规模一律不猜。
- 没有数字时，用可观察的定性证据，例如完成的模型/报告、方法被采用、反馈导致的修订、问题被定位、后续研究问题形成。
- 相关不等于因果。材料只证明参与时，不写成用户单独造成团队结果。
- 不把工具名称本身当能力；说明工具在什么判断或任务中被怎样使用。

## 弱项处理分支

只在官方 prompt 要求，或申请材料中存在评审很可能注意且不解释会造成实质误读的异常时考虑写入。用户不愿披露敏感原因时，尊重边界，不通过持续追问迫使披露。

使用：**必要语境—补救—学习—准备度**。

1. **必要语境**：只给理解异常所需的最少真实信息；不编借口，也不要求诊断、创伤或家庭细节。
2. **补救**：用户采取了哪些具体行动改变状况或恢复轨道？
3. **学习**：形成了什么可观察的判断、习惯、方法或认识变化？
4. **准备度**：有哪些后续证据表明现在更能承担目标项目要求？

若没有补救或准备度证据，不用修辞制造“成长闭环”；把它记为风险，考虑省略、压缩，或让用户选择是否提供有限说明。若官方另有 optional statement，应检查是否比主文书更适合承载该信息。

## 段落验收

- 主题句只发出一个主要资格判断，段内每句都服务该判断。
- 至少有一项可回查的本人动作和一项可观察证据。
- 能力词可以从证据合理推出，不靠形容词自评。
- 未来连接响应 prompt，并由过往证据支撑；没有保证不可控制的结果。
- 专业术语只保留讲清工作所需的部分，领域专家能判断深度而不必解码名词堆。
- 没有捏造数字、个人化团队成果、混入其他申请人的示例或突破披露边界。
- 正文动词、测试阶段和指标含义不超过 evidence map 中的 `claim_ceiling`；`future-only` 没有写成已有能力。
- 段落与 CV 等材料事实一致，但不只是把 CV bullet 扩成完整句。
