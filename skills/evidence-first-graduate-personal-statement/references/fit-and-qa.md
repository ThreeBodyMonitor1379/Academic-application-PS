# 项目 fit 路由与最终 QA

当官方 prompt 要求 why programme、research fit、资源使用或候选人贡献，或正式草稿进入最终检查时读取本文件。

## Fit 的优先路由

若 `two-way-academic-fit` 可用，优先使用它完成当前官方来源核验和双向 fit 论证，再把来源、核验日期、进入链和贡献链回写 `PS_REQUIREMENTS.md`、`PS_EVIDENCE_MAP.yaml` 与 `PS_QA_REPORT.md`。不要在本编排器中复制一个较弱的同义流程。

若该 skill 缺失，执行以下最小 fallback：

1. **确认任务需要 fit**：从当期官方 prompt 或说明判断；若明确不要求，记录不适用，不为了定制感硬加 fit。
2. **只取当前官方来源**：优先项目/院系主页、课程目录、官方教师或实验室页、实践/论文机制页。记录 URL、标题、适用周期和核验日期。第三方页面只作线索。
3. **选最小充分资源集**：只保留真正改变申请者计划的具体机制；不要求固定列出 2–3 位教师，也不默认教师正在招生、课程必然可选或资源保证开放。
4. **建立进入链**：`申请者目标或缺口 → 官方机制 → 将如何使用 → 可观察的发展结果`。
5. **建立贡献链**：`既有证据 → 可迁移能力 → 目标环境中的可行行动 → 有边界的贡献`。
6. **做三项检查**：换校名后逻辑是否仍成立；每项贡献是否有过往证据；每个高漂移事实是否为当前官方信息。

无法访问官方页面时，保留 fit 骨架与待核实项，不生成确定性的课程、教师、招生或资源事实。不得虚构教师联系、实验室席位、未来成果或机构会选择用户的原因。

## 正式草稿 QA

逐项把结果和证据定位写入 `PS_QA_REPORT.md`；不要只勾选“通过”。

### 1. Prompt 与边界

- 每个官方问题都有响应；字数、字符、文件、语言和格式满足当前要求。
- PS/SOP 标签没有覆盖实际 prompt；主文书与额外 short answers 没有无意义重复。
- 用户禁用素材、披露边界与非目标得到尊重。
- 当前官方要求高于任何通用页数、12pt 字号、1 英寸边距或固定教师数量建议。

### 2. 事实与证据

- 每个承重事实可回指 `PS_EVIDENCE_MAP.yaml` 的来源和状态。
- 日期、学位、成绩、论文/项目状态、数字和专名与材料一致。
- 团队结果与本人动作分开；未核实主张、占位符和来源示例没有进入正式稿。
- 能力结论没有超过证据，意愿没有伪装成已具备能力。

### 3. 轨迹与段落

- 过去经历说明其如何形成当前问题或能力，当前积累连接到可发展而非绑定的未来方向。
- 选材按论证价值而非机械时间线；转折有因果连接，不强造命定故事。
- 每段一个主要主张，主题句可被快速识别；无关信息已删除、迁移或补足连接。
- 开头无论个人化还是直接式，都响应 prompt 并进入未来方向。

### 4. Fit

- 若相关，至少一条进入链和一条证据支持的贡献链闭合。
- 每个项目事实有当前官方 URL 与核验日期；校名替换测试不能无损通过。
- 不把声望、城市偏好、教师名单或泛泛赞美当成 fit。
- 不保证导师、课程、名额、录取或未来影响。

### 5. 读者负荷与语言

- 核心判断和最强证据容易扫描；长段已拆分，段落顺序反映重要性。
- 专业细节足以让领域读者判断，本可删除的术语没有用来炫技。
- 抽象自评已替换为行动与证据；重复 CV、套话和可批量替换句已删除。
- 若交付为排版文件，再按目标方要求检查页面密度、字号、边距、断页和导出效果。CMU PDF p. 4 的就业写作混合示例只支持一般可读性提醒，不能升级为招生格式规则。

### 6. 发布状态

- readiness gate 已通过，或报告明确记录 `user_override: true` 与未解决风险。
- 用户需最终确认的专名、数字、敏感措辞和未来方向已列出。
- `ready-for-user-review` 只表示可供用户最终审阅，不表示录取保证，也不自动授权提交或对外联系。
