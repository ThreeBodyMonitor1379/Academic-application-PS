# 逐问质询与 readiness gate

在开始质询、选择下一问、决定是否正式起草或处理提前退出前读取本文件。

## 来源边界

一次一问、先探索可发现信息、向用户提供当前判断与推荐答案、用歧义评分控制退出，以及用户可知情提前退出，适配自 MIT-licensed [`max4c/skills` 的 `grill-me`](https://github.com/max4c/skills/blob/main/skills/grill-me/SKILL.md)。`CURRENT READ`、`FRAMING RECOMMENDATION` 的申请文书格式，以及下列五个招生维度，是本产品的领域化适配，不是 CMU handout 的方法。

外层栏目保持用户指定顺序、回答状态机、答案所有权和“忘记/没有/不记录”的止损规则，来自 2026-08-26 研究生申请访谈中可观察的交互决策。这里只保存外显协议，不保存或声称还原隐藏思维链。

## 提问前置条件

1. 先读已有五份项目工件，并遵守 `source_scope`。用户明确排除的成型 PS/CV 不得读取、借用措辞或作为动机来源。
2. 先查目标项目当期官方页面；记录 URL、标题、周期与核验日期。能查到的内容不问用户。
3. 把文件事实、用户陈述、解释性判断和未知项分开。任何推断只能写成 tentative，不得写成个人事实。
4. 先判断质询模式。用户提供表格、栏目或明确要求“按顺序/依次”时进入顺序保持模式；否则进入自适应模式。
5. 每轮只选择一个会改变选材、主张强度、归因或合规性的缺口；不为完整感追问不会改变写法的细节。

## 两种质询模式

### 顺序保持模式

外层严格维护用户给出的 `section_cursor`，不得因为某项经历更丰富而跳过、重排或永久离开当前栏目。栏目内仍然自适应：只问当前最承重的一个问题，充分后移动到下一子项或栏目。用户可以明确要求跳过、返回或只补某一栏目；这会更新 cursor，而不是重启整套问卷。

用户未提供栏目但要求按表质询时，使用以下可裁剪的默认框架：

1. **求学动机**：课程/研究接触、活动、阅读、经用户自愿提供的童年或家庭背景、个人志向。
2. **学术准备**：相关高分课程、沉淀能力、科研/项目/比赛/毕业论文、助教或校内工作、论文/会议、交流经历。
3. **实践经历**：校园活动、实习、工作、创业、个人创作或自媒体；必要时追问时间、地点、角色、问题、本人行动、结果与能力。
4. **职业目标**：行业/岗位、选择原因、机构类型或例子、希望产生的影响、当前短板及项目资源如何补足。
5. **为什么该学校和专业**：经官方核验的课程、实践机会、资源与师资；历史或排名只有在与选择逻辑相关且来源可靠时使用，不做泛泛赞美。
6. **补充经历**：专业以外、能改变评审判断且申请人愿意披露的内容。

童年、家庭、健康、身份、财务与创伤从来不是必答项。用户说“没有”或不愿披露时直接跳过。

### 自适应模式

用户没有指定顺序时，从五维中选择当前最高风险缺口；不得为了复制默认框架而机械扫描全部栏目。每轮仍遵守一次一问、状态记录和止损规则。

## 每轮固定格式

每一轮只能出现一个需要用户回答的问题。路径、目标项目或交付格式等澄清也算质询轮，必须使用同一格式。可给上下文和建议，但不得用多个问号、并列子问或“请依次回答以下几点”绕过一次一问。

```text
CURRENT READ
- Confirmed: 已由材料、官方来源或用户明确确认的事实。
- Tentative: 当前解释，但仍需用户确认。
- Gap: 这轮只处理的一个高影响缺口。

FRAMING RECOMMENDATION
- Recommended frame: 基于现有证据建议怎样界定或呈现；不是替用户新增事实。
- Why: 该 framing 如何响应 prompt 或降低误读风险。

QUESTION
[一个可直接回答的问题]
```

如果没有足够事实形成 framing，就明确推荐先保持该项为空，并说明为什么；不要为了给建议而编造答案。用户可拒绝推荐或修正 `CURRENT READ`。

## 答案所有权

Agent 可以：

- 从授权材料提取事实，核验公开和官方信息。
- 指出概念、因果、术语或指标解释中的错误，并说明拟写时应怎样降级。
- 推荐 framing、提问顺序和证据取舍。

Agent 不可以替用户决定或生成个人动机、感受、顿悟、价值判断、因果连接、披露选择或职业志向。技术纠错只改变拟写主张，不能变成“用户已掌握该知识”的新经历。

只有用户明确要求“介绍一下并给一版回答”“给我候选说法”等时，才能输出候选答案。候选答案必须：

1. 仅使用已确认事实；推断单独标记。
2. 明确写为 `CANDIDATE WORDING — REQUIRES USER CONFIRMATION`。
3. 不自动写入中文大纲或正式稿，直到用户接受或修改。

## 回答状态机

每个回答或子项必须使用下列状态之一；不得把它们互相偷换：

| 状态 | 含义与后续动作 |
|---|---|
| `confirmed` | 用户明确确认，或可靠材料直接支持；可按对应证据等级使用。 |
| `tentative` | 当前解释可能成立，但仍需用户确认；不得写成确定事实。 |
| `unknown` | 当前没有答案或证据；只在会改变主张上限时追问。 |
| `forgotten` | 用户曾经历但记不起关键细节；最多做一次决定性恢复尝试，然后降级或排除。 |
| `none` | 该栏目确实没有内容；记录后移动，不把空缺包装成经历。 |
| `not_involved` | 用户明确未参与某动作或结果；这是负边界，禁止归为个人贡献。 |
| `excluded_by_user` | 用户说“不重要/不记录/不要写”；后续不得静默重新引入。 |
| `do_not_disclose` | 用户不愿披露；不追问原因，改用非敏感证据。 |
| `conflicting` | 来源互相冲突；解决、降级或排除前不得进入正式稿。 |

## 模糊回答的追问顺序

对诸如“我做了很多”“效果很好”“这让我成长”“我很感兴趣”等回答，不立即改写成强主张。根据现有证据从下列链条中选择最早缺失且最重要的一项，每轮只问一项：

1. **具体场景**：当时要解决的具体问题或约束是什么？
2. **本人动作**：用户本人做了什么，团队做了什么？
3. **选择依据**：为何采用该方法或作出该取舍？
4. **结果**：有什么可观察产物、变化、反馈或后续用途？没有数字也可以。
5. **认知变化**：这件事具体改变了什么理解、判断或工作方式？
6. **未来连接**：它为何支持目标项目中的下一步，而不是泛泛“继续学习”？

并非每段经历都必须覆盖六项。只追问足以支持拟写主张的内容。若用户不知道、无法核实或不愿披露，在回答层记录 `unknown / forgotten / do_not_disclose`，在证据层另记 `unverified`，随后转向其他证据；不得无限追问。

### 止损与恢复规则

- `forgotten`：只有当一个额外问题会改变经历是否保留、允许动词或量化口径时，才可再问一次。仍无法恢复就使用定性下限或排除。
- `none`、`not_involved`、`excluded_by_user`、`do_not_disclose`：立即结束该分支，不再换一种问法施压。
- 缺少包版本、参数或日期，但这些细节不会改变主张时，不追问。
- 缺少核心代码归属、验证环境或数字口径且会改变主张时，问一次决定性问题；仍未知则降级。
- 后续发现新文件证据时可以重新打开 `unknown/forgotten/conflicting`；不得无证据自行升级状态。

## 五维评分

只允许使用 `0 / 0.25 / 0.5 / 0.75 / 1`。评分对象是当前项目工件与可写事实，不是用户回答了多少问题。

| 分数 | 含义 |
|---|---|
| 0 | 清晰：没有会改变选材、论证或合规性的未解决歧义。 |
| 0.25 | 基本清晰：仅有轻微缺口，且不会要求写作者猜测承重事实。 |
| 0.5 | 混合：部分明确，部分仍需可能改变文本的判断。 |
| 0.75 | 大多模糊：方向存在，但写作者很可能替用户作关键选择。 |
| 1 | 完全模糊：承重信息缺失，正式起草只能大幅猜测。 |

五个维度都必须评分：

- **Target**：目标项目、学位、申请周期、官方 prompt、受众与硬约束是否已核验。
- **Evidence**：核心主张是否有可追溯事实，个人与团队归因、数字和冲突是否处理清楚。
- **Trajectory**：选定经历是否形成有因果依据、不过度承诺的过去—现在—未来方向。
- **Fit**：若任务要求 fit，当前官方资源与候选人目标/贡献是否双向闭合；若已由官方要求确认不适用，可记 0 并说明。
- **Boundaries**：篇幅与格式、题目边界、披露红线、禁用事实、非目标和遗留不确定性是否明确。

计算：`aggregate = (Target + Evidence + Trajectory + Fit + Boundaries) / 5`。证据 gate 只在 `aggregate <= 0.2` **且每个单项都 `<= 0.25`** 时通过。处于两个等级之间时，选更高的歧义分数；不可通过删除维度、用更多问题数量、把未知项假设为真，或让一个 `0.5–1` 的关键维度被其他低分平均掉。

## 报告与门禁

把每次正式 gate 判断写入 `PS_QA_REPORT.md`，并在 `PS_PROJECT_STATE.md` 更新阶段：

```text
READINESS REPORT
Target:      0.25 — [证据或缺口]
Evidence:    0.25 — [证据或缺口]
Trajectory: 0.00 — [证据]
Fit:        0.25 — [证据或不适用理由]
Boundaries: 0.25 — [证据或缺口]
Aggregate:  0.20 — PASS / HOLD
Hard cap:   PASS only if every dimension <= 0.25
Evidence gate: PASS / HOLD
Outline approval: pending / approved [version and time]
Drafting gate: allowed only when evidence gate passes or is explicitly overridden, and outline approval is recorded
```

分数必须与理由一致，平均值按实际数值计算，并单独检查 hard cap。例如 `1/0/0/0/0` 的平均值虽为 `0.20`，仍必须 `HOLD`。证据 gate 通过后停止低价值追问，生成中文大纲并进入 `outline-review`；只有用户明确批准该版本，才能进入起草。

## 用户提前退出

用户可随时终止质询。此时：

1. 停止追问并尊重退出。
2. 仍按当前证据评分并展示完整报告。
3. 在 `PS_QA_REPORT.md` 记录 `user_override: true`、时间、未解决风险及其可能影响。
4. 在 `PS_PROJECT_STATE.md` 记录是“仅交接工件”还是“按风险继续起草”。
5. 先生成带风险标记的中文大纲并取得明确批准。若之后继续起草，只用已知事实；删除无依据主张或清楚标记待核实内容。不得把未过门稿标为可提交成稿。

知情退出不是门禁通过，不能把分数改低来迎合用户；`user_override` 也不能替代中文大纲批准。
