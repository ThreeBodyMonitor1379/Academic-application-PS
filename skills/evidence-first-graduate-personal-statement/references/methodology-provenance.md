# 方法扩展来源与三重验证

## 来源范围

- 内容类型：长对话/访谈。
- 日期：2026-08-26。
- 主题：研究生申请文书的证据质询、技术主张校准、中文大纲、英文起草和排版 QA。
- 可使用内容：用户明确给出的交互要求、用户回答、Agent 可见的纠错与主张降级、停止追问和发布门禁。
- 禁止声称：模型隐藏思维链、逐 token 推理、未在对话中表达的申请人心理或个人事实。
- 隐私处理：不保存姓名、学校内部路径、身份字段或可识别项目组合；例子只保留匿名方法模式。

现有产品还组合了 CMU handout 与 `max4c/grill-me`。本次扩展不能反向归因给这些来源；来源边界以 `SKILL.md` 为准。

## 候选单元与三重验证

V1 检查至少两个独立语境；V2 检查能否外推到新问题；V3 检查是否足够独特，值得成为单独方法而非普通提醒。

| 候选单元 | V1 | V2 | V3 | 产品处理 |
|---|---|---|---|---|
| 用户 schema 外层保序、栏目内自适应 | 通过：学术、实践、职业和 fit 栏目均适用 | 通过：能处理“只补某一栏”而不重启 | 未独立通过：与既有一次一问协议高度相关 | 并入 `grilling-protocol.md` |
| 回答状态机与质询止损 | 通过：课程、项目、实验、活动均出现未知/遗忘/排除 | 通过：可判断何时停止追问新的项目细节 | 未独立通过：属于质询控制协议 | 并入 `grilling-protocol.md` |
| 最大可辩护主张 | 通过：公开实现、团队项目、仿真、硬件集成、性能数字等独立语境 | 通过：可外推到微调模型、田野调查、团队活动等新经历 | 通过：同时约束机制、来源、贡献、验证、指标和归因 | 建成独立内部 reference |
| 指标语义与 benchmark 门禁 | 通过：吞吐、时延、精度、图像质量、主观评价 | 通过：可推导新指标不能互相替代 | 作为独立 skill 不通过：属于最大主张的判定部件 | 并入 claim calibration |
| 未完成项目的边界化反思 | 通过：硬件集成与训练中断等语境 | 通过：可判断何时保留限制与学习 | 未独立通过：与 evidence paragraph/trajectory 相邻 | 并入 claim calibration |
| 中文大纲明确批准门禁 | 通过：个人动机、技术归因、职业目标与 fit 均涉及答案所有权 | 通过：可处理用户要求直接写但证据未闭合 | 通过：把 evidence readiness 与 applicant ownership 分成两道门 | 并入 drafting/release |
| LaTeX/PDF 发布检查 | 不足：来源对话只有一个完整发布场景 | 通过 | 未通过：已有 LaTeX/PDF 专门能力 | 只做路由与 QA reference，不建新 skill |

用户在规划阶段明确选择“单一完整 skill”而非多个 sibling skills，因此通过的单元以 progressive disclosure 的内部 references 组合进现有端到端编排器。它们不会另建顶层 trigger，也不会与 prompt、trajectory 或 fit skills 抢调用。

## 可预测性样例

以下均为抽象或虚构问题，不是申请人事实：

1. **公开模型微调但训练/测试划分重叠**：主张门禁会允许“exploratory adaptation”，禁止“robust improvement”。
2. **团队组织大型活动，申请人只负责摄影宣传**：允许个人职责和团队结果分句，禁止“led the entire event”。
3. **运行界面显示吞吐提升，但采用批处理**：允许在给定设置下的 throughput 观察，禁止自动写 per-item latency reduced。
4. **用户只说“不记得参数”**：若参数不改变主张则停止；若决定原创/复现或定量口径，只追加一次决定性问题。
5. **用户明确“不记录这段经历”**：状态为 `excluded_by_user`，即使后续大纲缺素材也不得重新填回。

## 局限与维护规则

- 对话案例不能证明该方法提高录取率，只能证明它能约束证据、归因和写作流程。
- 技术 sanity check 不是同行评议；高风险或陌生领域仍需权威资料、代码、日志或领域专家。
- 默认六部分访谈框架来自一次硕士申请场景；用户的官方 prompt 和自定义栏目始终优先。
- 中文大纲确认适合强调申请人内容所有权的完整工作流；只做局部诊断时不应强制创建全部工件。
- 官方项目、课程和上传要求会变化，任何旧核验不能跨周期复用。
